设计目标

要解决什么问题

当前 Claw Assistant 已具备 ReAct 执行、多工具调度、长期记忆、通知推送等能力， 但用户交互仍以"一问一答"为主。本文档定义三个面板，将交互范式从被动应答升级为： 对话即操作（面板01）→ 推理可追溯（面板02）→ 后台主动守护（面板03）。

维度现状（被动）目标（主动）对应面板
交互方式文本一问一答对话驱动结构化看板，双向联动面板01
过程透明只看到最终回答思考/工具/反思/产物全链路可视面板02
主动服务用户问才做后台持续监控，按需打扰面板03
用户画像前提

本文档场景以在校大学生为典型用户（有课表、追番、英语打卡、预算敏感）。设计应具备可扩展性—— 监控维度、安全边界、通知频率均可按用户画像动态调整，而非硬编码。

 快捷操作气泡来源

底部"把龙井村换成美院""加一个室内备选"等快捷操作，生成规则如下：

  • 来源：Agent 在生成行程回复时，同步推荐 2-3 个最可能的后续操作，基于当前上下文 + 用户历史偏好。
  • 生成方式：LLM 在回复末尾输出 quick_actions 结构化字段，前端渲染为可点击气泡。
  • 点击行为：点击后等价于用户发送该文本，进入正常对话流程。
  • 可关闭：用户可在设置中关闭快捷推荐。

 AI配图触发时机
  • 触发条件：行程看板首次生成时自动配图1张（封面图）；用户可手动点击"换一张"重新生成。
  • 不自触发：行程变更（增删改）不自动重新生成配图，避免浪费API额度。仅当用户主动请求时生成。
  • 额度限制：每次行程最多生成3张配图，超出需用户确认。
  • 风格选择：用户可从预设风格中选择（新海诚风、扁平插画风、水彩风等），默认按用户历史偏好选择。
 看板直接编辑入口
  • 拖拽排序：行程项可拖拽调整顺序，自动重算时间。
  • 点击编辑：点击任一行程项展开编辑面板，可修改时间、地点、备注。
  • 右键菜单：右键行程项可"删除""复制到另一天""替换为备选"。
  • 手动添加：看板底部有"+"按钮，可手动添加自定义行程项。
  • 变更回写：所有手动编辑都会通过 API 提交，后端将变更摘要注入对话上下文。

 失败场景示例

原文档只展示成功流程。以下为工具调用失败时的处理示例：

思考
需要查询《千古情》可预订场次，调用票务API。
工具失败
ticket.search(show=千古情, date=2026-09-07) → API超时（10s），返回空结果
反思
票务API不可用，改为用搜索引擎查公开信息。先告诉用户"正在查询场次"，不阻塞行程看板生成。
降级工具
web.search(query=千古情 杭州 周六 场次) → 找到官方页面，有19:00和21:00两场
产物生成
行程看板已创建，《千古情》暂排周日19:00，标注"票价待确认"。

处理原则：工具失败时 Agent 自动降级到备选方案；无法降级时在回答中明确告知用户"该信息暂时不可用"，不阻塞其他流程。

 多步骤展示策略
  • 展开/折叠：默认只展示每步的摘要（1行），点击展开详情。
  • 分页：超过8步时，前6步折叠为"前6步已执行"，只展示最近2步 + 最终产物。
  • 实时流式：每步完成即推送到前端，不等全部完成。用户可看到"正在思考..."的实时过程。
  • 历史回看：对话结束后，时间线永久保存在对话记录中，可随时展开回看。

[修订] 安全边界 · 详细规则
⚠花钱操作：只比价、不下单。涉及支付的决策（买票、订酒店、打车）必须用户点击确认后才执行。预算超预估20%时额外提示。
⚠通知频率：默认每天最多打扰3次（可配置：1-10次/天）。打扰定义：弹窗通知 + 声音。静默通知（只写入通知中心，不弹窗）不计入。
⚠静默时段：用户可设置免打扰时段（如23:00-08:00），此时段内只写入通知中心，不推送弹窗。
⚠不可逆操作：删除文件、取消订单等不可逆操作，必须二次确认。
⚠自主级别可调：用户可在设置中调整 Agent 自主级别（低/中/高），影响哪些操作需要确认、哪些可自动执行。
 性能预期
  • 目标响应时间：简单对话 ≤ 3s；单工具调用 ≤ 8s；多步复杂任务 ≤ 30s。
  • 流式展示：超过3s的请求必须流式推送中间步骤，用户看到"正在查天气..."而非空白等待。
  • 超时处理：单步工具调用超过15s自动降级或跳过，不阻塞整体流程。

 后台持续任务技术可行性

Web 应用（Spring Boot + SQLite）维持7x24小时后台监控的技术方案：

  • 定时任务调度：使用 Spring @Scheduled 或 TaskSchedulerService，每个监控域注册独立的定时任务，按各自频率轮询外部 API。
  • 频率策略：天气 1次/3小时；票价 1次/2小时（临近出行前24h加频到1次/30min）；课表 1次/天（前一晚检查）；信息猎手 1次/6小时。
  • 夜间静默模式：23:00-07:00 自动降频（所有任务频率减半），仅保留课表和天气通道，其他暂停。
  • 持久化：监控任务状态写入 notification_outbox 表，应用重启后自动恢复未完成的定时任务。
  • 通知推送：在线用户通过 SSE 实时推送；离线用户下次登录时在通知中心看到未读。
"主动服务"计数定义
计入不计入
Agent 主动发起的检查（天气、票价、课表等轮询） 用户主动发起的对话
触发条件后的通知推送 后台任务执行但未触发任何条件
自动更新行程/追番列表等数据操作 记忆存储、上下文维护等内部操作
 "打断你0次"判定规则

打扰 = 弹窗通知 + 声音提示。不打扰 = 只写入通知中心，无弹窗无声音。

条件行为示例
静默时段内只写入通知中心23:00-07:00 的一切通知
当天打扰次数已达上限只写入通知中心已打扰3次后，后续均静默
非紧急事项延迟到下次活跃时段英语打卡提醒推迟到09:00
紧急事项立即打扰（不计入次数上限）考试时间变更、极端天气预警
用户标记的优先事项立即打扰用户设置的"票价低于¥200立即告诉我"
 用户控制入口

面板需提供以下用户控制能力：

  • 全局开关：一键暂停/恢复所有后台监控（"我要清净一会"按钮）。
  • 单维度开关：每个雷达维度可独立暂停/恢复。
  • 自主级别：低（全部需确认）/ 中（默认，花钱操作需确认）/ 高（小额自动执行，仅大额需确认）。
  • 通知频率：可调整每天打扰上限（1-10次）和静默时段。
  • 手动触发：点击雷达上任一维度可"立即检查一次"。
 活动日志可操作项

日志每条记录可执行以下操作：

  • 跳转到对话：点击日志条目跳转到触发该操作的源对话。
  • 标记已读/未读：管理通知状态。
  • 设置为提醒：将该事项转为定时提醒。
  • 反馈：标记"有用/没用"，用于 Agent 学习用户偏好。
  • 撤销操作：如果 Agent 自动执行了某操作（如更新追番列表），用户可撤销。

竞品差异化

与 ChatGPT/豆包/通义等通用助手相比，Claw Assistant 的差异化在于：(1) 对话与结构化看板双向联动（而非纯文本回复）；(2) 后台持续监控 + 雷达可视化（而非只在前台被动等待）；(3) 明确的安全边界和可调自主级别（而非黑盒自动化）。这三点应在设计文档和产品文案中重点突出。
